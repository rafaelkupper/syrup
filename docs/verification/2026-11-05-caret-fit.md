## Revision 2026-11-05: the clipboard carries the fitted text

the maintainer tested the Debug build and asked that what gets pasted be the final fitted text, including manual Command-V with automatic paste off. The contract changed accordingly:

- The preference no longer requires automatic paste. It acts when Accessibility is trusted, and onboarding's Taste page holds it off.
- `AppState.sentenceFit` reads the cursor once, just before the clipboard write, at the pinned editor while it is current or otherwise at the focused element of the app in front. The clipboard, Copy result again, and any paste get the fitted text. History keeps the exact result.
- Automatic paste pastes the fitted clipboard with Command-V, so the special typed delivery for fitted text was removed. Smart spacing reuses the same read.
- Streaming fits the clipboard with the context the typist used, so typed text and clipboard match. Paste Last fits the exact history result again for its own target.

Focused run: `CaretFitDeliveryTests`, `CaretFitStreamingTests`, `AppStateTests`, and `PauseTransformationTests`, 139 tests in 4 suites, all passed. New cases cover automatic paste off, missing Accessibility, onboarding's Taste page, Paste Last re-fitting, failed typing with the typed strategy, and streaming clipboard parity. Real editors remain unverified.
