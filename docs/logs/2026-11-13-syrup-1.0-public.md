## Anomalies

- **Apple agreement.** The notary service first answered 403, "A required agreement is missing or has expired". The maintainer accepted the pending agreement.
- **Notary credentials.** After that the saved profile answered 401, invalid credentials. The maintainer supplied a new app-specific password, and `notarytool store-credentials` validated and saved it to the login Keychain under the same profile name. The password was not written anywhere else.
- **Archive failure.** `script/release.py` passed `CODE_SIGN_IDENTITY` and `DEVELOPMENT_TEAM` on the `xcodebuild` command line, which also applied to Swift package resource bundles. The app target now reads `SYRUP_CODE_SIGN_IDENTITY` and `SYRUP_DEVELOPMENT_TEAM`, and the script passes those. This path had only been exercised with mocked commands since the publisher settings left the manifest.
- **Private feed.** The script reads the live feed over public HTTPS, which returns 404 while the repository is private. For this release only, a wrapper outside the repository supplied the feed from the authenticated GitHub API (`repos/<owner>/syrup/contents/appcast.xml`) and ran `script/release.py` unchanged otherwise. The script's check that the clone and the feed agree still ran. Once the repository is public, the script works without the wrapper.

- Stopped the running older private build (1.0 build 13, previous bundle identifier), moved it from Applications to the Trash, and copied the new app to Applications.
