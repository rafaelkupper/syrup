What is sent, and where?

Syrup keeps each dictation's audio on this Mac, at most 50 recordings or 7 days. In idle time it transcribes the audio again on this Mac. It may send the two transcripts, with your glossary terms to skip, to your AI provider (OpenAI-compatible) to spot misheard words. Audio never leaves the Mac. Suggestions wait here for you to add or dismiss.

Welcome guide
Goes through permissions, language, and AI provider again. Keeps your current settings.
Example data: workflows, results, stats, apps, and glossary terms are invented for the mockup. The provider URL and model are your current settings.

Home

  • Opens with one line that says what to do: hold this key and speak. Pausing turns that line into a Resume button.
  • The workflow sentence shows what the next dictation will do, and every word in it can be changed. It replaces four labeled pickers and the Edit button.
  • “then paste it / copy it” uses the existing auto-paste setting, so you can see on Home whether results paste.
  • Items that need attention appear only when something is wrong, and each has its fix button.
  • Stats are one row of four figures, a 26-week activity grid, and top apps with their real icons.
  • Recent shows the full result text with its workflow's color. Copy and Paste show on hover. A new result stays highlighted until you've seen it. As today, it never shows which app a result went to, because history stores no app identity.
  • Clear History asks to confirm. Today it deletes everything at once.

Built with

  • Settings { TabView { Tab(…) } } for the toolbar tabs. ⌘, and Open Syrup… both open it, through openSettings.
  • The sentence: a small Layout that wraps words, with Pickers in .menu style and .buttonStyle(.borderless).
  • The grid: Swift Charts RectangleMark, which reads as one chart in VoiceOver instead of 252 cells.
  • App icons come from NSWorkspace.icon(forFile:), looked up once and cached.

Workflows

  • The list and the editor sit side by side, so there is no back button and no list page that is mostly empty.
  • The row shows each workflow's shortcut, and the active one has a check. Make Active is in the ⋯ menu, not hidden in a right-click.
  • The editor starts with the same sentence as Home, then has three sections: Input, Output, and When it runs.
  • Spoken edits (self-corrections, formatting commands) move here from Recording, under Output on Translate workflows, and note that the setting is shared by every Translate workflow.
  • The workflow's own shortcut and its apps move here. The Shortcuts page no longer lists workflows.
  • Corrections become a two-column table.
  • Colors come from the action (blue Translate, purple custom instruction, gray Transcribe), so no new setting key is needed.

Built with

  • HSplitView or HStack with a List(selection:) and a grouped Form. +, −, and ⋯ form a standard list bar of borderless buttons.
  • + is a Menu of the existing templates.

Dictation

  • Covers how you start a dictation and how Syrup listens. It merges Shortcuts and the microphone part of Recording.
  • The Fn setup paragraph moves into a disclosure. The toggle keeps one line.
  • Speech models move to Models, and spoken edits move to the Translate workflow.
  • The indented child toggle uses the standard disabled state. It no longer uses a hand-set 45% opacity.

Built with

  • KeyboardShortcuts.Recorder, Picker(.segmented), a DisclosureGroup for the Fn help, and the existing detent Slider with its scale labels.

Delivery

  • Renamed from “After Dictation”.
  • A one-line diagram at the top shows where the result goes. It changes when pasting is off or Accessibility isn't allowed.
  • The three paste options stay under their parent toggle, and their captions are shorter.
  • The sound label now says when it plays.

Built with

  • Grouped Form, with an HStack of Labels for the diagram.

Models

  • Brings together the two things that do the work: speech recognition, which runs on the Mac, and the writing provider.
  • Each model row shows which workflows use it, so you can tell whether it's safe to delete.
  • Parakeet Ultra and Redux have no measured bars or final download sizes in code yet (SpeechEngine.swift holds placeholders). The mockup says “Not measured yet” and leaves the size out.
  • Test Connection keeps its last result in place: how long the server took, and when.

Built with

  • The existing SpeechModelControls, plus a Picker(.radioGroup) with captions for the provider.

Glossary

  • Terms are a sortable two-column table with search, Add Term, and an Import/Export menu.
  • The 70-word paragraph under Learning moves into “What is sent, and where?”.
  • Suggestions sit above Learning, because that's where you act on them.
  • A footer explains the difference between the Glossary and a workflow's Corrections.

Built with

  • Table with editable TextField cells, .searchable, and a DisclosureGroup.

Privacy

  • “Granted” becomes “Allowed”, the word macOS uses.
  • Each data type shows where it goes: this Mac in green, a server in orange.
  • The footer names any workflow whose provider differs from the default.
  • Delete Stats… sits next to its toggle and asks before deleting.
  • The tab badge counts permissions that need attention, as the Privacy sidebar badge does today.

Built with

  • Grouped Form and LabeledContent. The badge comes from .badge(_:) on the tab item.

General

  • Kept as a short last tab. Putting the login and update toggles in a menu would hide them.
  • The version row says when Syrup last checked.

Built with

  • Grouped Form, SMAppService, and Sparkle's SPUUpdater, as today.

Review of the current window

Reviewed from source, without the detector, because the window is native. Screenshots come from the installed 0.8 build (2026-11-05). The uncommitted working tree supplied stats, the model list, and spoken edits. Nothing was profiled, so the performance notes below are about code, not measurements.

Does it look made for Syrup?

No. Without the window title, nothing on screen says Syrup. The onboarding has its own amber world with a dripping band, and the app icon is honey. The main window looks like System Settings. You asked to stay native, so the mockup gets its character from what native apps already allow: one color per action used everywhere a workflow appears, a workflow sentence you can edit, real app icons, and a Recent list that shows your actual words. It does not reskin the controls.

Priority issues

P1Three concepts are each split across two pages

WhyThe speech model is in a workflow and in Recording. The provider is in AI Provider and in a workflow. Shortcuts are in Shortcuts and in a workflow. Spoken edits are in Recording but only affect Translate. You have to remember which page owns what.

FixEight tabs, with one place for each concept. Workflows owns everything that belongs to a workflow. Models owns both engines. See the tab map below.

P1Home doesn't say what will happen or what just happened

WhyA status pill, a pause toggle, a headline, four pickers, Edit, stat tiles, a heatmap, and Recent all have the same weight. Recent cuts off the result, its most useful content.

FixA status line, then the workflow sentence, then attention items only when needed, then stats in one row, then Recent with the full text and its workflow color.

P1The workflow editor is a long push page

WhyYou leave the list to edit, then scroll past Name, the Active row, five Input rows, and about 100 words of captions before reaching what the workflow does. Duplicate and Delete sit in a section of their own.

FixA list and editor side by side. A sentence summary first, then Input, Output, Corrections, and When it runs, with short captions. Delete moves to the list bar.

P1Clear deletes history with no warning

WhyWhen history is kept across restarts, one click on a small link deletes every result for good.

Fix“Clear History…” asks to confirm and names the result count. Delete Stats… also asks.

P2Captions repeat the control or bury the rule

WhyThe glossary learning caption is 70 words and the Fn caption is 60. The spoken symbols toggle lists 20 words inline.

FixOne line per caption. Edge cases go in a disclosure. See the label table below.

Who gets stuck

Power user. Can't make a workflow active without right-clicking, and has no ⌘1 to ⌘8 for pages. Has to open each workflow to see its shortcut. In the mockup, shortcuts show in the list, ⋯ has Make Active, and each tab gets a ⌘ number from the Window menu.

First-time user. Sees “OpenAI-compatible”, “Base URL”, “streaming”, and “Parakeet v3” before ever dictating. Recent says “Nothing yet” and doesn't suggest what to try. In the mockup, an empty Home shows an example to say and its result.

Polish, optimize, and delight

Polish (to do when building)

  • Use semantic text styles everywhere (.title2, .caption), not fixed point sizes.
  • One status capsule style, used only for state: Allowed, Saved, Not allowed. Active becomes a check in the list.
  • Remove SettingsPage and its title inset workaround, because the Settings window draws its own title.
  • Disabled child rows use .disabled only.

Optimize

  • Use one TimelineView for the whole Recent section, not one per row.
  • Cache app names and icons by bundle ID, and build the activity weeks once per stats change.
  • Run the provider check when the window opens and when the provider changes, not on every Base URL keystroke.
  • Then measure window open and tab switch times with the Instruments SwiftUI template. None of this is measured yet.

Delight

Syrup should feel like it already knows what you want: one sentence tells you what the next dictation will do, and what you just said is waiting where you can find it.

  • The workflow sentence is Syrup's own: read it out loud and it describes the run.
  • A new result stays highlighted until you've seen it, then fades. If Reduce Motion is on, it doesn't fade.
  • An empty Home suggests a phrase to try in your dictation language, with the result Syrup would give.
  • Your numbers, like time saved and your streak, say what they measure.
