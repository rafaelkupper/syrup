# Syrup — Architecture

## Stack

- **Language/UI:** Swift 6, SwiftUI `MenuBarExtra` + SwiftUI settings. The app is `LSUIElement` and uses bundle identifier `org.syrup.SyrupApp`; the product name and Swift module are `Syrup`.
- **Minimum target:** macOS 26 (Tahoe) — required for the `SpeechAnalyzer`/`SpeechTranscriber` API, which is the default transcription engine and drives the live transcript in every voice run. (If broader OS support ever matters, an `SFSpeechRecognizer`-based `Transcriber` could be added behind the existing protocol.)
- **Project generation:** [XcodeGen](https://github.com/yonaskolb/XcodeGen) — the project is defined in `project.yml`; the `.xcodeproj` is generated and git-ignored. This keeps the project diffable and agent-editable (no hand-editing `pbxproj`).
- **Dependencies (SwiftPM):**
  - [`sindresorhus/KeyboardShortcuts`](https://github.com/sindresorhus/KeyboardShortcuts) 2.4.0, pinned exactly — global hotkey with a native recorder UI, no Input Monitoring permission needed.
  - [`FluidInference/FluidAudio`](https://github.com/FluidInference/FluidAudio) 0.18.0, Apache-2.0, pinned exactly. It runs the opt-in Parakeet Ultra, Parakeet Redux, Nemotron Streaming 3.5, and Parakeet Unified EN speech models with Core ML. Canary 180M Flash also runs on Core ML, through Syrup's own `CanaryModel`, not FluidAudio. XcodeGen cannot disable its package traits, so its TTS and diarization code compiles but is unused.
  - [`sparkle-project/Sparkle`](https://github.com/sparkle-project/Sparkle) 2.10.1, used only by `UpdateController` for signed in-app updates.
  - No SDK for the LLM: the OpenAI-compatible call is a single `URLSession` POST; a client library would add nothing.
  - `script/check-boundaries.sh` (run by `script/ci_test.sh`) fails when one of these SDKs, `Speech`, or `AVFoundation` is imported outside its folders in any import form, when `Core/` names a type from another folder, when a non-UI folder names anything from `App/`, when a `RunConfiguration` is built outside `RunConfigurationBuilder`, or when any source file uses an audio file API. See IMPLEMENTATION.md.

## Pipeline

The whole app is one pipeline driven by a small state machine:

```
            hotkey down                 hotkey up / toggle off
   ┌──────┐ ───────────► ┌───────────┐ ───────────► ┌──────────────┐
   │ idle │              │ recording │              │ transcribing │
   └──────┘ ◄─────────── └───────────┘              └──────┬───────┘
      ▲        Esc/cancel                                  │ final transcript
      │                                                    ▼
      │        clipboard written         ┌─────────────┐
      └───────────────────────────────── │ translating │
                 (or error state)        └─────────────┘
```

States: `idle`, `recording`, `transcribing`, `translating`, `error(reason)`. The menu bar icon is a pure function of this state. Transcription starts in the background as soon as recording starts, but the visible state remains `recording` until the user releases the hotkey, toggles recording off, or reaches the configured maximum recording duration.

`requestStopRecording` takes a `RunStopReason`: `hotkey`, `menu`, `durationLimit`, or `failure`. A `hotkey` stop is a hold release or a toggle-off press, for dictation or revision. If the last buffer before release was under -45 dBFS, it stops at once, so a release after speech has ended adds no wait. Otherwise it starts a release tail so a last word spoken while releasing is kept. Capture continues and buffers keep reaching the live transcriber until the first buffer after release whose raw level is under -45 dBFS, or until 200 ms after release. The state stays `recording` during the tail. `ReleaseTail` is the pure decision over buffer levels and the deadline. `RecordingClock` supplies the deadline, and `PipelineRun.RecordingPhase` (`capturing`, `releaseTail`, `stopping`) records progress. The other reasons stop at once, and a failure during a tail ends it at once. Esc during the tail cancels through the ordinary cancel path. Further hotkey presses during the tail change nothing. In hold mode, a `hotkey` stop less than 300 ms after the press, measured with `RecordingClock` from `PipelineRun.triggeredAt`, is an accidental tap. It goes through `cancelRequested()` with no tail, so there is no feedback, history, provider request, or clipboard write. Dictation and revision holds share this check. Toggle presses and menu stops never discard. The duration guard auto-stops recording through the same state-machine path as a normal release, so useful speech still proceeds to transcription/translation while runaway toggle-mode recordings are bounded. Selected-text workflows take the direct `idle → translating` path: selection capture starts before delivery preparation and reads Accessibility off the main actor, and recording, transcription, key-release handling, and the duration guard are skipped. Cancellation (Esc or re-press during processing) before the delivery commit aborts the in-flight task, cancels the live transcription task when present, and returns to `idle` without touching the clipboard. Once clipboard write and success-history append commit delivery, both Esc and re-press are ignored until the short auto-paste tail finishes, so a committed run always completes its paste, feedback, usage count, and recording.

`RunConfiguration.purpose` selects a normal dictation, a revision, or a transcribe-only run. A transcribe-only run skips provider preparation and transformation, and its history record uses the `.contextual` snapshot so older builds can still decode persisted history. A revision snapshots the newest successful output before recording, transcribes the new speech as an adjustment, composes the revision instruction and mandatory clean-output contract, then transforms the captured output instead of the adjustment transcript. The selected provider receives that captured previous result plus the current revision instruction; when the provider is cloud-backed, both leave the Mac. No unrelated history or content is included, and neither value is logged. Revision provider configuration is captured at trigger time. Apple On-Device creates no session for the empty revision placeholder; after transcription it creates a session with the actual revision instruction. Context-bearing Apple runs prepare after selection capture so the prepared instruction is complete.

The production pipeline uses real `AppleTranscriber` followed by a `TextTransformer` selected by `AppSettingsTransformerProvider` for each run. `AppState.init` takes every service as a parameter; only `AppState.production(settings:speechModels:)` in `SyrupApp.swift` builds the real ones, and tests build fakes through `AppState.fixture(...)`. `RunConfigurationBuilder` (`Sources/Translation/`) is the only place a `RunConfiguration` is assembled, with one entry point each for a workflow run (with or without captured selection), a revision before and after its adjustment is transcribed, and a retry; `AppSettings.runInputs(for:)` reads the settings a run is built from once at the trigger. Provider selection lives in Settings and applies to the next run without restart. At trigger press, `AppState` resolves the workflow and snapshots dictation locale, provider, and history transformation metadata. A voice run opens the microphone first; the opt-in selection read and the delivery-target capture run beside it and finish before transcription and any early transformation use the instruction, so a slow Accessibility reply never costs the first words; audio buffers in the meantime. Selected-text runs use the captured selection as transformer input and skip the audio path. `RunConfiguration.contextText` retains selection data only for the active task. Later Settings changes apply to the next run, not the one already active. At trigger time, `AppSettingsTransformerProvider.snapshot(for:)` (the `TransformerSnapshotting` seam) resolves only the selected provider into a `TransformerSnapshot`: immutable endpoint/model/key or Codex executable/model, plus whether pause transformation may send unfinalized input. Test and fixed sources conform to `TransformerSource` instead. The OpenAI-compatible configuration goes through `OpenAICompatibleSettingsConfigurationResolver`, the same precedence the Settings connection test uses, with keys compared after trimming; reading the small key file at trigger time measured about 14 µs at the median. Every transforming run prepares its transformer once at the start (`prepareTransformer`), from that snapshot, and delivery uses only that prepared transformer, so an endpoint edited mid-run reaches the next run. A run that reached delivery without one would be a bug; Debug builds stop at an assertion, and Release builds fail the run with a message (`PipelineError.transformerNotPrepared`) rather than ending it silently. Preparation errors can stop recording early. `PipelineRun` owns the run ID, child tasks, stop continuation, delivery target, and snapshots of trigger mode, delivery, cue, accuracy, and revision-glossary preferences. Every asynchronous cleanup rechecks ownership before changing observable state. In a Debug build only, if there is no saved local API key and the process has a complete `OPENAI_COMPATIBLE_URL`, `OPENAI_COMPATIBLE_API_KEY`, and `OPENAI_COMPATIBLE_MODEL` environment configuration, the provider uses that environment configuration as a non-persistent development fallback. A Release build ignores those variables, so Settings always shows what a run uses. Saved endpoint settings and local API key still take precedence. `script/launch_syrup_with_env.sh` loads the same variable names from ignored `.env` for an intentional Debug-app launch without printing secret values.

### Transcription

`Transcriber` is a protocol so the engine is swappable:

```swift
struct TranscriptionRequest: Sendable {
    var locale: Locale
    var vocabulary: [String] = []
    var onPartialTranscript: (@Sendable (String) -> Void)? = nil
    var preferFastResults = false   // honored by Apple's SpeechTranscriber; other engines ignore it
}

protocol Transcriber: Sendable {
    func transcribe(_ audio: AudioBufferSequence, request: TranscriptionRequest) async throws -> String
}
```

New options go into `TranscriptionRequest` rather than new `transcribe` overloads.

- **v1: `AppleTranscriber`** built on `SpeechAnalyzer` + `SpeechTranscriber` (macOS 26+) — fully on-device, free, private. Audio buffers are converted to the analyzer's preferred `AVAudioFormat`, fed as `AnalyzerInput`, and finalized with `finalizeAndFinishThroughEndOfInput()`. Results arrive as an async sequence; volatile (partial) results drive the live transcript in the recording cue.
- **Opt-in: `ParakeetTranscriber`** runs Parakeet Ultra or Parakeet Redux, moondream's post-trainings of NVIDIA Parakeet TDT 0.6B v3, through FluidAudio when a workflow selects one. See Speech engines below.

**Dictation locale** is an explicit user setting (e.g. `pt_BR`), not auto-detected — `SpeechTranscriber` transcribes one locale at a time, and a fixed locale is what makes accuracy good. The app refreshes `SpeechTranscriber.supportedLocales` at startup so the menu-bar Dictation picker is usable before Settings is opened; Settings also refreshes the same list when it appears. Both go through `AppSettings.refreshActiveDictationLocale`: it reads the active workflow and its locale before the check awaits Speech, and stores a replacement only on that workflow and only if its locale is still the one checked, so switching workflows or editing the language meanwhile never puts the replacement on the wrong workflow. App-provided locale IDs are normalized through `SpeechTranscriber.supportedLocale(equivalentTo:)` and compared by BCP-47 identifier to avoid `pt_BR`/`pt-BR` mismatches. The default is Portuguese (Brazil), stored as BCP-47 `pt-BR`; a one-time settings migration rewrites old accidental English defaults (`en`, `en-US`, or `en_US`) to `pt-BR`, then preserves later user choices.

**Model assets** are managed by a `TranscriberAssetManager`:

1. On locale selection, check `SpeechTranscriber.installedLocales`.
2. If missing, run `AssetInventory.assetInstallationRequest(supporting:)` and surface download progress in Settings (models are downloaded once, then work fully offline).
3. Transcription is blocked with a clear message until the selected locale's assets are installed; the hotkey path kicks off preparation but does not wait on a model download.
4. Preparation is deduplicated by normalized locale, with independent tasks and progress. Preparing shortcut locales does not change the locale displayed in Settings; the shortcut observer only refreshes when its required locale set changes.
5. Once a normalized locale is known to be installed, it is cached in memory so later warm dictation runs can skip repeated supported-locale and installed-locale lookups.

Speech-recognition authorization is requested at transcription time via `SFSpeechRecognizer.requestAuthorization`; microphone authorization remains owned by `AudioRecorder`.

Volatile results drive the live recording cue. Audio feeding and result monitoring run concurrently: a recognition error cancels the feed and ends recording without waiting for key release. Finalization and result collection each have a 15-second timeout; failure cancels the underlying analyzer without waiting indefinitely for framework cleanup. Only completed transcription enters transformation.

`AppleTranscriber` supplies speech vocabulary through the macOS 26 Speech context API. For a non-empty composed speech vocabulary it creates an `AnalysisContext`, assigns the first 100 exact terms to `contextualStrings[.general]`, and calls `SpeechAnalyzer.setContext(_:)` before analysis starts. This does not establish a recognition benefit. The [synthetic recognition evaluation](docs/verification/2026-11-01-recognition-eval.md) reports the measured effect and its limits. Mishearing hints remain prompt-side only. An empty composed vocabulary creates no Speech context.

Speech vocabulary can also include a default-on built-in list of common English tech terms. User glossary terms take priority, case-insensitive duplicates are removed, and the combined list remains capped at 100 entries; built-ins enter only the Speech context and never enter the LLM prompt. Settings can export the personal glossary as pretty-printed JSON using the existing `glossaryV1` `GlossaryList` Codable shape.

### Speech engines

`SpeechEngine` is `apple`, `parakeetUltra`, `parakeetRedux`, `nemotronStreaming`, `parakeetUnifiedEN`, or `canaryFlash`, stored per `Workflow` as `speechEngine` and snapshotted into `RunConfiguration`. Workflows saved before the field existed decode as Apple, and an engine name this build does not know also decodes as Apple, so a newer build's choice cannot make the workflow list undecodable. `parakeet_v3`, which 0.9 offered, decodes as `parakeetUltra` and is saved under the new name on the next write. `SpeechEngine.supports(localeID:)` holds the language tables: for Parakeet Ultra and Redux the 25 ISO 639-1 subtags on v3's model card, which both keep, for Nemotron the 28 languages of the 32 locales NVIDIA lists as transcription-ready or broad-coverage, and for Canary en, de, es, and fr. Workflow normalization resets Parakeet to Apple whenever the dictation locale leaves that table. Revisions use the active workflow's engine. Older builds ignore `speechEngine` and drop it on their next write, which returns those workflows to Apple.

FluidAudio types stay inside `ParakeetEngine` and the streaming engines' `StreamingSpeech.swift`; `ParakeetEngine` is one actor per model (`AsrModelVersion.ultra` or `.redux`) that owns it once loaded. Both use v3's tokenizer, window, and decoder, so the code below is shared. Its download fetches files with `ModelHub.download` rather than `AsrModels.download`, which would also compile each model for the Neural Engine in the staging folder before Syrup moves it. Both run on the Neural Engine, FluidAudio's default. Redux's 2-bit encoder compiles there for several minutes on its first load, but then finished real clips in 80 ms at the median against 143 ms on the GPU. FluidAudio's logger is set to fault-only with no console mirroring before any FluidAudio engine works, because its debug output can include transcript text: `SpeechModelCatalog.live()` calls `FluidAudioLogging.silence()` first, and `ParakeetEngine`, `NemotronBackend`, and `ParakeetUnifiedBackend` call it again when built, wherever that happens; a test pins each. `ParakeetTranscriber` conforms to `Transcriber`. It converts buffers to 16 kHz mono with the same `AnalyzerAudioConverter` Apple uses and decodes a dictation of up to 60 seconds once at release, through FluidAudio's own long-audio chunking. Each decode ends its text as a finished sentence, so cutting continuous speech into 15-second segments put a period and a capital at every cut. Past 60 seconds it cuts only at the center of the quietest 300 ms of the last 15 seconds, and only when no frame there reaches speech level, or anyway once 75 seconds have accumulated. Cutting mid-pause leaves silence on both sides of the boundary; cutting at the first quiet frame dropped words that ended a segment. Release therefore waits for one decode of at most 75 seconds, which took 274 ms on a busy measuring Mac, and the run holds at most about 10 MB of 16 kHz audio, the pending 75 seconds plus a copy of the segment being decoded, whatever the recording length. A segment is decoded only if it holds speech. After a one-pole high-pass near 76 Hz, at least 100 ms of its 20 ms frames must sit 6 dB above its own quietest tenth. Parakeet returned short words such as "Yeah." for noise-only audio, so a noise-only press, or room noise left after the last cut, adds no words. A final segment shorter than 0.5 seconds is padded with silence to FluidAudio's minimum. The locale's language subtag is passed as FluidAudio's script filter. Parakeet ignores the speech vocabulary: FluidAudio's CTC vocabulary boosting raised term recall in evaluation but inserted a glossary term into an ordinary sentence, so the glossary reaches Parakeet runs only through the prompt and through Apple's preview context.

When a run's engine is downloadable and its `SpeechModelManager.state` is `.ready`, `runPipeline` splits the captured audio with `AudioFanOut`. `AppleTranscriber` receives one copy with `.fastResults` and drives the live transcript, and `ParakeetTranscriber` receives the other and produces the delivered transcript. Apple's accurate mode delayed volatile results by about 11 seconds in measurement, and its text is only a preview and backup here. A Parakeet error or an empty Parakeet transcript returns Apple's transcript when Apple produced one, and the run ends as "Nothing heard" when neither engine has text. When both engines have failed, even while the key is still held, the run stops capture at once and shows Apple's typed `TranscriptionError`. An Apple error alone never stops a Parakeet run, so missing Apple assets only remove the preview. The fan-out keeps feeding one output after the other's consumer stops, and fails only a lagging output with an overflow. The Apple task is cancelled as soon as the transcript exists. Cancellation cancels both tasks before any clipboard write, including while the run waits on Apple after a Parakeet failure.

A model that is not ready never delays a dictation. The run uses Apple alone, asks the manager to load a model already on disk, and after a non-empty transcript posts `State.fallbackNotice` once per launch. The notice names only the model state. A cancelled run or accidental tap posts nothing.

Streaming engines (`SpeechEngine.isStreaming`) use the same split, with one difference: the model drives the live transcript and Apple produces only the backup. `StreamingTranscriber` converts buffers to 16 kHz and feeds a `StreamingSpeechBackend`, one small actor per FluidAudio manager. `StreamingSpeechEngine` runs backend calls strictly in order, so a cancelled run finishing a chunk cannot interleave with the reset that starts the next run. Each `begin` opens a numbered session, and `append` and `finish` name theirs: a call from an earlier session is refused when it joins the queue, so a cancelled run still draining its 16 kHz converter cannot feed its last samples into the next run, and the transcriber checks cancellation before each drained append. A streaming model counts as installed only when every file its manager loads is there (`ModelFiles.present`; a compiled model counts once its `coremldata.bin` is), not just Nemotron's `metadata.json` or Unified's encoder, so Retry after a failed load of a partial folder downloads instead of loading it again. `NemotronBackend` feeds 300 ms of silence first because the model dropped opening words without it, and it uses the multilingual `2240ms` variant, one download for every language. `ParakeetUnifiedBackend` fetches only the int8 streaming files, not the 11 GB repo. Measurements are in [the speech model verification](docs/verification/2026-11-02-speech-models.md). `CanaryModel` runs the Core ML export at `aufklarer/Canary-180M-Flash-CoreML`, pinned to revision `ca44e0f`, and downloads its 14 files directly, checking each size and every published SHA-256. It computes NeMo's log-mel features with Accelerate as the bundle's `config.json` specifies, runs the encoder over a fixed 10-second window, prefills the nine-token prompt with the workflow's language as both source and target, then decodes greedily one token per step. `CanaryTranscriber` cuts longer dictations at the quietest moment of each window's last 4 seconds and decodes each piece while recording continues, as Parakeet does at 60 seconds. When a window holding speech decodes to nothing, which happened on a long test clip, `transcribeRecovering` splits it at its middle pause and decodes both halves. Apple drives the live preview and is the fallback, as for Parakeet. `CanaryModel.swift` and `SpeechSegmenter.swift` depend only on system frameworks, so the recognition evaluation compiles the same code.

`SpeechModelManager` is `@MainActor @Observable`, one per downloadable engine, held by `SpeechModelCatalog`. Downloads land in a hidden `.partial-<folder>` beside the model and move into place when complete (`SpeechModelCatalog.stagedDownload`), replacing an incomplete folder already there, which would otherwise fail every retry; a complete model already there is kept and nothing downloads. `remove()` deletes only that model and its unfinished download. It has states `unsupported`, `notDownloaded`, `downloading(progress)`, `downloaded`, `loading`, `ready`, and `failed(message)`. Only `download()` uses the network. Apart from the v3 handover below, it runs only after the user presses Download in Models, in a workflow's editor, or on Home. It fetches the model from Hugging Face into `Application Support/Syrup/SpeechModels/<folder>/`, keeps `SpeechModels` at 0700, reports monotonic progress, then loads. The manager's rules are a pure state machine, `SpeechModelMachine`: each click and each finished job is an event, and the machine returns the new state and the effects the manager runs (start a job, cancel the running download, delete the folder being replaced, read the disk). Downloads, loads, and removals of one model run one job at a time, in the machine's queue. Each click that changes what the person asked for moves a generation on; a job from an earlier generation is stale, so its result does not change the state. When a job's task begins it reports `began`, and the machine skips a download or load that went stale after it was queued, so a Cancel or Delete clicked before it started still stops it; a removal always runs. Cancel beside the progress bar (`cancelDownload()`) cancels the running download and returns to `notDownloaded`, keeping finished files in staging for the next attempt, and Delete while downloading cancels first, then removes the model and its staging folder. A download started right after Cancel waits until the cancelled one has stopped, since both use the same staging folder, and a cancelled download that finished anyway is not moved into place. When the queue drains, the machine reads the disk once: a model that landed as it was cancelled, or a Delete that failed after a later click, shows as `downloaded` instead of `notDownloaded`. A finished job never leaves `downloaded`, so a model deleted outside Syrup still shows as downloaded until its next load fails, as before. `loadIfDownloaded()`, which runs at every dictation trigger, reads nothing itself; the load it starts reads the disk once when it finishes. Delete shows the model as not downloaded at once, so nothing can start a load of it while it is removed, and a load in progress finishes without becoming ready before the files go. An accepted Delete always removes the files, even when Download was pressed meanwhile: the download waits behind it and starts from nothing, and only the removal's own state update is skipped. `SpeechModelExplorerTests` runs every interleaving of clicks and job completions against the machine, breadth first, with a simulated disk: a queued job begins in a step of its own, so clicks can come between; a download can report progress, land and then return, or fail first; a load can fail; and a removal can fail keeping the model or after deleting its files (about 1,930 states and 8,200 transitions from each starting disk, queues up to three). At every state it checks that one job runs at a time, that a stale download or load never does its work, that an idle state agrees with the disk, that nothing is left downloading or loading, that Retry after a failed removal only removes, that an accepted Delete runs before any later download, that the older folder of a handover exists exactly while the handover is pending, that progress from a stale download changes nothing, and that an unsupported model stays unsupported. `SpeechModelConformanceTests` replays every explored transition without a progress report, up to a queue of one (about 1,500 from each starting point), on the real manager with a real folder, fakes that wait for the test's command at each job's start and each operation, and file permissions that make a removal fail. It checks the manager's state, the model on disk, and the older folder against the machine after every step, and reports two operations waiting at once or a manager that does not settle as a difference. `SpeechModelManager.Operations.willBeginJob` is the hook it holds; it does nothing in the app. `SpeechModelSequenceTests` still runs every sequence of up to three back-to-back operations. FluidAudio's downloader and Canary's own both stop on task cancellation. `loadIfDownloaded()` loads a model already on disk, for Parakeet with `AsrModels.loadLocal`, which never downloads, followed by a one-second silent warm-up decode. It acts only in the `downloaded` state and moves to `loading` before returning, so repeated calls start one load. A failed load stays failed until the user presses Retry or Delete. `AppState` calls it at launch and on workflow changes when the active, shortcut-bound, or routed Voice workflows include a downloadable model, and Settings calls it when a workflow selects one. Loading never happens on the release path. The first load from a new location compiles the model for the Neural Engine: 7.9 seconds for Ultra and 6 minutes for Redux on the measuring Mac. Later loads took 0.7 and 11.4 seconds. `remove()` unloads the model and deletes its folder. The model stays loaded until removal or quit. At launch, `SpeechModelCatalog.replaceRetiredParakeetV3()` starts the Ultra download when a `parakeet-tdt-0.6b-v3` folder left by 0.9 exists, so workflows that chose v3 keep a model on this Mac without another click. The handover is `SpeechModelManager.replace(_:)`: the v3 folder is deleted only once Ultra is on disk, or at once if Ultra already is. A failed download leaves v3 in place, and its folder makes the next launch try again. Cancel or Delete on Ultra deletes v3 too, so a handover the person stopped does not start the 632 MB download again at every launch. Without that folder it does nothing. `ParakeetEngine.isSupported` is false on Intel, where the manager reports `unsupported`, Settings hides Parakeet, and runs use Apple. The universal build still compiles FluidAudio for x86_64. Retry repeats what failed: after a failed removal it removes again, and after a failed download or load it loads a model that is already on disk instead of downloading it again, which would fetch it into staging and then fail to move it onto the existing copy.

### Spoken edits

The raw default-off preferences `handlesSelfCorrections` and `handlesSpokenFormatting` reach `PromptBuilder` as `DictationOptions(selfCorrections:spokenFormatting:)`. A caller that passes no options gets `.off`, so no path turns them on by omission. `PromptBuilder` adds each instruction to the Translate base only when it is on. `AppSettings.dictationOptions(input:provider:)` returns `.off` for selected-text input, because a "no wait" inside selected text is content, and for a provider whose `TranslationProvider.supportsSpokenEdits` is false (Apple On-Device). The provider is the run's: `AppSettings.provider(for:)` (workflow override, else the global provider) for new runs and selection runs, and the chosen provider for a retry. Custom instructions and Revise never receive them. When either is on, `PromptBuilder` also appends `spokenEditsLanguageReminder(targetLanguage:)`, because with several commands in one dictation the model sometimes left the text untranslated. The workflow editor's `SpokenEditsRows` shows the same gate: `SpokenEditsNote` disables the toggles for Apple On-Device without writing the stored values, and for OpenAI-compatible warns and names the recommended model, or acknowledges it when `baseURL`'s host is `api.cerebras.ai` and the model is `gpt-oss-120b`. With both off, the Translate prompt is byte-for-byte the earlier one. `ModelOutputNormalizer` strips a wrapper quote pair only when no matching quote sits inside, so `"a" and "b"` survives, and keeps it when the speaker asked for quotes. `ModelOutputNormalizer.requestsQuotes(input:instruction:)` decides that: the instruction contains `PromptBuilder.spokenFormattingInstruction` and the transcript says "in quotes", "open quote(s)", "close quote(s)", "entre aspas", "abre aspas" or "fecha aspas" as whole words, case- and accent-insensitively. The OpenAI-compatible (including a JSON reply to a streaming request), Apple On-Device and Codex CLI atomic paths, `AppState`'s streaming completion, and `StreamingTypist` (which then stops holding back a leading quote) all use that one decision. Custom, selected-text and Revise instructions never contain the constant, so they keep stripping.

### Usage stats

`runPipeline` calls `recordUsage` after a dictation or Transcribe run is delivered, so revisions, selection runs, retries, and failures never count. It measures the transcript and passes on only numbers and the frontmost bundle identifier, read after delivery so it adds nothing to hotkey-to-recording time. Speaking time is the sum of gaps between audio buffers louder than `ReleaseTail.quietLevel`, falling back to trigger-to-release when no level arrived. `UsageStatsStore` updates memory on the main actor and writes the whole file through the `UsageStatsDisk` actor, so delivery never waits on the disk. Each write or delete waits for the previous one, so a slow write can never land after Delete Stats and bring the numbers back; `flush()` awaits the queue. Delete Stats clears the screen, then deletes the file after any queued write; if the file survives, the stats still on disk come back with an error instead of returning silently at the next launch. The file is `Application Support/Syrup/usage-stats.json` at 0600, not UserDefaults, because it grows by a small entry per day and app.

### Audio capture

`AudioRecorder` is the production `AudioRecording` implementation. It requests microphone permission with `AVAudioApplication`, creates an `AudioQueue` only for the active recording, applies the selected input device UID before starting capture, and yields interleaved Float32 `AVAudioPCMBuffer` values through `AudioBufferSequence`, an `AsyncThrowingStream<AVAudioPCMBuffer, any Error>`. Each recording passes through `AudioLevelTap`, which forwards a buffer before reporting its raw RMS in dBFS for the release tail and a smoothed level for the cue. Buffers hold 4096 frames, about 85 ms at 48 kHz, so a release after speech ends waits for at most one buffer. `finish()` accepts the AudioQueue stop callbacks before closing the stream, preserving the final captured buffers, and runs queue shutdown off the main actor. Callbacks run on the session's own dispatch queue, so after `AudioQueueStop` it waits for that queue (`callbackQueue.sync {}`): a final callback the stop dispatched runs while the session is still draining, instead of finding it stopped and dropping the last buffer. `stop()` discards pending callbacks for cancellation or failure, and also waits for the queue before `AudioQueueDispose`, so no callback is reading a buffer when it is freed. A capture generation prevents a permission response from restarting a canceled microphone. Raw, level-tap, and analyzer queues each have a 256-buffer limit; overflow terminates the stream with a typed error. The level tap preserves upstream errors, including failures after key release. Run failure checks prevent those errors from reaching delivery. Start failures are reported after one setup attempt; missing selected microphones fall back before queue creation, but AudioQueue setup failures are not blindly retried with the same inputs.

`CoreAudioInputDeviceCatalog` enumerates input-capable devices with `kAudioHardwarePropertyDevices`, filters for devices with input channels, and exposes the Core Audio device UID, display name, sample rate, and channel count to Settings and recording. The selected microphone UID is stored in `AppSettings`; an empty UID means system default. When a specific device is selected, `AudioRecorder` verifies the UID is currently available and sets the input queue's `kAudioQueueProperty_CurrentDevice` before `AudioQueueStart`. If the selected device is no longer present, recording falls back to the system default instead of crashing. `InputResolution` uses a device snapshot and the current IOKit `AppleClamshellState`. When the lid is closed and the effective input is `BuiltInMicrophoneDevice`, it selects the first other input, including a headphone-jack input. If none exists, it throws a typed recording error. The replacement supplies both the queue UID and audio format, without changing the saved microphone preference. An unavailable lid state preserves ordinary device selection.

`OutputDucker` is an actor with `lower()`, `restore()`, and `restoreAfterCrash()`. `SyrupApp` creates one and asks `AppState` to run `restoreAfterCrash()` at launch; the inert test host never does. `AppState` chains every ducker call on one task, so a lower and its restore stay ordered, and recording start and stop never wait for that chain. `PipelineRun.lowersOtherAudio` snapshots `AppSettings.lowerOtherAudioWhileRecording`, a raw bool defaulting to false, at trigger. A lowering run lowers after the recorder starts and restores after `finish()`, so returning audio cannot keep the release tail open. `clearRunTracking()` restores again for cancellation, failure, and supersession; the repeated restore is a no-op. The success path waits up to 1 second for the chain before the success sound. A ducker error is logged with its error code only and never fails a run. The Settings toggle sits in General > Recording. `CoreAudioOutputVolumeController` reads the default output's settable virtual main volume, falling back to settable channel volumes. An output with no settable controls is a no-op. Channel key zero denotes virtual main volume; other keys denote CoreAudio output channels.

Before lowering to 0.3 of the original values, the ducker synchronizes one JSON-free UserDefaults property-list restore record containing the device UID and original and lowered values. Repeated lowering preserves the original record. Restoration resolves the recorded UID even after the default output changes, restores only controls still within 0.015 of Syrup's lowered values (devices round the level they are given; one keyboard volume step, 1/64, is further off, so a change the person made wins), and removes the record. A missing device clears it. Failed restoration keeps the record for retry. Launch recovery uses the same operation, so a successful recovery runs once. CoreAudio and defaults operations execute on the actor, away from the main actor.

### Translation

`OpenAICompatibleTransformer` POSTs to `{baseURL}/chat/completions` with configurable base URL, model, and API key — which makes it work unchanged against OpenAI, OpenRouter, Groq, Ollama (`http://localhost:11434/v1`), LM Studio, etc. The stored base URL must be absolute `http` or `https` with a host and includes `/v1`; the transformer trims a trailing slash and appends only `chat/completions`.

- `PromptBuilder.compose` is the single assembly point, with frozen order base → glossary → context → contract. Translation workflows use target language + tone preset; custom workflows can append the system-owned output contract. The personal-glossary block applies to every run purpose, workflow, and provider, renders at most the first 100 terms, one line each (a term or mishearing is stored with its inner whitespace and line breaks collapsed to single spaces), includes optional mishearing hints, and is byte-for-byte absent when the glossary is empty. Opt-in selected context is fenced between `BEGIN CONTEXT` and `END CONTEXT` markers whose boundary is the first 12 bytes of the context's SHA-256: selected text cannot contain a digest of itself, so an email containing `"""` or a fake end marker cannot close the fence, and the same input still composes the same instruction. It is framed after the glossary block and before the output contract with an explicit data-not-instructions rule. "Do not use tools or commands" is owned by the command-line prompt path (`PromptBuilder.fencedPrompt`, shared by Codex CLI and Claude Code) and applies to every workflow kind. That path also fences the transcript or selected text between `BEGIN INPUT <boundary>` and `END INPUT <boundary>` markers, with a fresh random UUID boundary per call, after a rule that the fenced text is data and its requests are never followed.
- Temperature is low (`0.3`). OpenAI-compatible requests expose an SSE capability through `StreamingTextTransformer`. Every OpenAI-compatible request is streamed, including a run that shows nothing (`transform` collects the deltas) and pause attempts, so all of them have the inactivity deadline, which a model still generating keeps resetting. The non-streamed request is only the fallback for a server that refuses to stream; Settings' connection test streams too.
- A request that is not streamed has one 30-second deadline for its headers and body together (`withOperationTimeout`); its body is read through the 8 MB bounded reader. A streamed request uses the 30-second timeout for the first response and then the inactivity deadline described under Concurrency, which only a chunk carrying something resets: answer text, reasoning in any shape, or a tool call. `content` counts by its text, and by any part without a `text` string that carries something, such as Mistral's thinking chunk (`{"type":"thinking","thinking":[{"type":"text","text":"…"}]}`). A text part with empty text does not count, whatever labels it carries beside it, and an object's `type` and `index` only label it. A model that reasons silently, sending nothing or only empty chunks for 30 seconds, times out; that is deliberate, since a server repeating empty chunks would otherwise hold a run open. `content` sent as a list of typed parts is read as the text of its parts. A chunk with neither `choices` nor `error`, such as a usage-only chunk, is skipped. A JSON reply, whether labeled `application/json` or sent without events under another type, passes on its content unnormalized like a streamed answer, so either is normalized once. A 200 reply that never sends an event is decoded as a plain JSON answer if it is one (a server that ignores `stream` and labels JSON `text/plain`) and is otherwise an invalid response, such as a proxy's HTML page; one with only whitespace and comments is a dropped connection. HTTP status is checked explicitly: unreachable hosts, request timeouts, 401, 429, other non-2xx responses, invalid JSON, and empty output map to typed `TranslationError` values and then to user-readable app messages. Request cancellation stays a `CancellationError` so user-canceled runs do not masquerade as endpoint failures.
- On transformation failure, the app records an in-memory failed history item, offers "Copy transcript instead", and notification actions can copy the transcript or retry by record ID only. The transcript is written to the clipboard only after the explicit user action.
- `transformWithUsage` is the non-streamed request: it returns transformed text and optional provider token usage, and runs use it only as the fallback for a server that refuses to stream. Runs and the connection tester both go through `transform`, which streams, so Test connection sends what a run sends and a proxy that breaks streaming fails the test too. A 400, 422, or 501 reply that rejects `temperature` (models that accept only their default), by naming it as the parameter whatever the code, string or number, or in its message as some routers do, gets the same request once more without it, streamed or not; both paths read those replies the same way, and any other rejected parameter is not retried. Any rejection body that mentions `temperature` counts, whatever its shape. Once a request without it has gone through, the endpoint and model are remembered for the session, so later requests leave it out from the start instead of paying a rejected request every run. The transformer does not emit `max_tokens`; OpenRouter rejects that parameter for `openai/gpt-5.4-mini`, and production dictation must never cap long dictated output. Settings uses `OpenAICompatibleEndpointTester` with a tiny `"hi"` request for the Test connection button.

`AppleOnDeviceTransformer` uses FoundationModels (`SystemLanguageModel(guardrails: .permissiveContentTransformations)`, `LanguageModelSession`, `GenerationOptions(temperature: 0.3)`) when Apple Intelligence is available. Every session it creates, prepared, per-call, or the fresh streaming-fallback session, uses that one permissive model, because Syrup transforms the user's own words and the default guardrails can refuse legitimate rewrites of sensitive topics. Availability still reads `SystemLanguageModel.default`. It is a first-class provider with honest availability UI: unavailable hardware, disabled Apple Intelligence, and model-not-ready states are surfaced as typed errors. It never builds prompts itself; it receives the composed instruction from `RunConfiguration`. Guardrail refusals and context-window overflow map to typed user-facing errors rather than silently falling back to a cloud provider.

Apple On-Device also exposes FoundationModels' cumulative `ResponseStream<String>` through `StreamingTextTransformer`. A snapshot-to-delta adapter emits only append-only suffixes and signals an atomic fallback if the SDK ever returns a non-extension snapshot. The capability contract provides a dedicated atomic-fallback hook: Apple implements it with a fresh session because the streamed session may be consumed, while the default delegates to normal atomic transformation. `StreamingTyping.hasPostedText` distinguishes a received-but-buffered delta from a successfully posted prefix. A fallback after visible text stops typing and completes through clipboard/history without a final paste, so it cannot duplicate the prefix; a fallback before any successful post may use normal atomic paste. Codex CLI and Claude Code intentionally remain atomic: each prints only its final message, so there are no tokens to stream.

`CodexCLITransformer` bills transformation to the user's ChatGPT/Codex subscription by shelling out to the locally installed Codex CLI (`codex exec`, prompt via stdin, result read from stdout, which carries only the final message, so no result file is ever written). The model defaults to empty, which leaves `--model` out so Codex uses the signed-in account's default; a fixed name can be rejected, as `gpt-5.4-mini` is for ChatGPT sign-ins. Settings fills its model picker from `codex debug models` (`CodexModelCatalog`: entries with `visibility` `list`, in `priority` order, read in about 0.2 s), offers Codex default and Custom, falls back to a text field when the catalog can't be read, and warns when a saved name is not in the account's list. This is explicitly the slower provider because each transformation launches a subprocess; OpenAI-compatible and Apple On-Device are the low-latency paths. The CLI owns OAuth login and token refresh (`~/.codex/auth.json`) — the app never touches tokens and has no API-key entry for this provider. Binary discovery is deterministic: saved absolute path, then `~/.local/bin/codex`, `/opt/homebrew/bin/codex`, and `/usr/local/bin/codex`; GUI `$PATH` is deliberately ignored. The child process environment is minimal: `HOME`, `PATH` from `CommandLocator.childPath` (the executable's own folder, then the Homebrew and system folders, so an npm `#!/usr/bin/env node` launcher finds its interpreter), plus `CODEX_HOME` when present. Exit status 127, a launcher whose interpreter is missing, maps to its own message. The prompt is never passed as an argv element because argv is process-visible. Codex echoes the prompt to stderr before its own messages, so failure text is matched only after the input's `END INPUT <boundary>` marker; the boundary is random per call, so the dictation cannot forge it, and a short dictation that says "rate limit" cannot read as a plan limit. The CLI is run in a fresh empty temporary directory with `--sandbox read-only`, `--skip-git-repo-check`, `--ignore-user-config`, and `--ephemeral`, then the temp directory is removed. Ephemeral execution disables Codex session persistence independently of Syrup history. Codex only rewrites text here, so `CodexCLITransformer.restrictions` also passes `approval_policy="never"`, `web_search="disabled"`, and `features.<name>=false` for the shell and exec tools, apps, plugins, browser and computer use, image generation and viewing, sub-agents, memories, and hooks. With Syrup's earlier flags, a model asked to run `head -1 /etc/hosts` printed the line; with these it reported no shell (codex-cli 0.167.2, 2026-11-13). They are `-c` overrides rather than `--disable` because `--disable` exits on a feature name an older CLI does not know, while an unknown `-c` key only warns. A test pins the whole argument list. The runner awaits the process's exit through its termination handler instead of blocking a thread. `StdinFeeder` writes the prompt through a non-blocking pipe, each chunk waiting for writability, with `SIGPIPE` disabled: a CLI that exits before reading its prompt reports its exit status instead of crashing Syrup, and one that stops reading holds no thread, so its timeout still fires. With the earlier blocking write, 28 concurrent runs of a CLI that never read a 1 MB prompt starved the cooperative pool for 9.7 seconds and the 1-second timeouts could not fire. The process runner (`Sources/Translation/CommandRunner.swift`, shared by both command-line providers) reads stdout and stderr through readability handlers and never blocks a thread on a read. After the process exits it waits at most `drainGrace` (500 ms) for the pipes to close, because a helper process that inherited them can hold them open indefinitely; before, a helper sleeping 3 s held a finished run, and its 1-second timeout, for 3 s. Stdout is capped at 4 MB, past which the process is stopped and the run fails with its own message, and stderr keeps only its last 64 KB. Cancel, timeout, and the stdout cap stop the CLI's whole process group, even after the CLI itself exited while the runner still waits for a helper holding its pipes, as long as the group has members: `Process` starts the CLI as a group leader and its helpers join that group, so SIGTERM and, after the grace period, SIGKILL go to the group, not just the CLI. The SIGKILL waits in a task of its own that nothing cancels, because the timeout race that requested it is cancelled as soon as the CLI exits on SIGTERM, and a helper that ignored SIGTERM must still be killed; it is sent only if the group still exists. A helper that starts its own group or session is out of reach. It logs privacy-safe timings for both command-line providers, in category `CLIProvider` with `tool=codex` or `tool=claude` (a fixed word, never the configured path), for spawn, first stdout/stderr byte when present, and process completion using only stage, ephemeral command ID, outcome, and duration.

`ClaudeCLITransformer` is the same idea for a Claude plan: it runs `claude -p --output-format text` once per transformation, with the instruction and the fenced input (`PromptBuilder.fencedPrompt`, shared with Codex) on stdin and only a fixed system prompt in argv. `ClaudeCLITransformer.restrictions` starts it with no tools (`--tools ""`), no MCP servers (`--strict-mcp-config`), no CLAUDE.md, skills, plugins, or hooks (`--safe-mode`), no slash commands, `--permission-mode dontAsk`, and `--no-session-persistence`; `--effort low` keeps one-shot rewrites fast. The environment is only `HOME`, `USER`/`LOGNAME` (the Keychain sign-in is found by user name), the same `CommandLocator.childPath` as Codex, the auto-updater and nonessential-traffic switches, and `CLAUDE_CONFIG_DIR` when set, so a stray `ANTHROPIC_API_KEY` in Syrup's environment cannot change billing. An app opened from Finder never inherits the shell's `CLAUDE_CONFIG_DIR`, so Settings has an optional account folder (`claudeConfigDirectory`, then the launch environment, then Claude's `~/.claude`). Paths are passed without a trailing slash, because Claude keys the sign-in by the exact folder string and `~/.claude-work/` reads as a different, signed-out account. A configured folder that does not exist fails before launch, because Claude would otherwise create it. ### Clipboard

`ClipboardWriter` is the production `PasteboardWriting` implementation. On success, `AppState` writes the translated text exactly once by clearing `NSPasteboard.general` and then setting the `.string` payload. The pasteboard seam throws `ClipboardError.writeFailed` if AppKit rejects the write, so the pipeline does not mark a run successful while leaving the clipboard empty. Before clearing, the writer snapshots restorable plain-text pasteboard data and restores it on replacement failure when possible. Restore snapshots keep at most 1 MB by default, and rich/unknown representations are not materialized, so a promised image or document is never rendered. The pasteboard has no size query, so the existing plain text is read once in full, as UTF-8 data, before the limit applies; a 200 MB text clipboard still costs one read of that size. If the write fails, Syrup restores what it captured and reports `ClipboardError.writeFailed` when the plain text came back, even if formatting was dropped, as it is for most real copies. It reports `ClipboardError.writeFailedPreviousContentLost` only when something did not come back: an item with no plain text (an image or file), text over the snapshot limit, or a restore the pasteboard refused. An item past the limit is lost on its own; the items that fit are still restored. It never tries to reconstruct skipped representations. A failed write keeps the run's result for Copy Result: the sentence-fitted text for the clipboard and the exact result for history, so recovery never stores the fitted version. Clipboard logs include only stage, ephemeral operation ID, duration, snapshot byte count, and whether data was skipped, never clipboard contents. Tests inject a unique `NSPasteboard` or fake pasteboard seam so automated coverage never clobbers the user's clipboard. The explicit transcript fallback uses the same writer only after the user chooses "Copy transcript instead."

Auto-paste is an opt-in tail after a successful clipboard write. With default-on target pinning, `DeliveryTarget` captures the triggering process and focused Accessibility element asynchronously. Paste validates both before and after its settle delay; streamed typing validates them before each flush. `DeliveryTarget.isCurrent()` is async and reads the focused element on a detached task, so a hung editor costs the check up to its 100 ms messaging timeout without holding the main actor (112 ms per check before, within idle jitter after, on 2026-11-13). The frontmost app is checked on both sides of that read (`DeliveryTarget.focusStillHeld`): someone can switch apps while it is pending, and the old app still reports its old field as focused, so a check made only before the read would let Command-V land in the new app. Typed text events set their modifier flags to none explicitly, because an event made from the session source carries whatever modifiers are held, so a Command-S pressed mid-stream would otherwise turn typed text into a shortcut. Moving to another field or tab falls back to the complete clipboard result. A pinned run with no captured target (Accessibility off, or no focused field at the trigger) is not an editor change: it reports the missing permission, or that no text field had focus. General settings can disable pinning for deliberate focus switching. Accessibility calls use a 100 ms per-message timeout. Selection capture also runs off the main actor with that timeout and retains its 20,000-character cap. After the final cancellation check, clipboard write and success-history append execute synchronously and mark the run's delivery committed. Cancellation is then ignored for that run while the existing ~50 ms post-write settle delay and Command-V attempt finish; cleanup clears the commit marker. `AutoPaster` first checks Accessibility trust, then refuses to synthesize Command-V while Secure Event Input is active. At paste time it resolves the V key from the current layout's Command layer, then its plain layer, then an ASCII-capable layout, with the physical ANSI V key as the last resort. This preserves Dvorak-QWERTY-Command shortcuts without changing the input source. `PasteStrategy.resolve` scans the frontmost bundle's framework version directories on each paste, without a cache, because an in-place browser update does not change the app bundle's modification date. Any four-component Chromium version with major 155 or 156 selects `typeText`; other bundles use `commandV(keyCode)`. Completed typed delivery uses the same `TypingStep` planner, event poster, target validation, and secure-input checks as streaming, without normalizing the finalized result again. A failed typing attempt keeps the successful clipboard result and reports the degradation. A stream that posted text skips both final delivery strategies. Auto-paste failures are degradations: the clipboard remains the source of truth, the run still succeeds, and the app posts a privacy-safe notification explaining why paste did not happen. The `auto_paste` metric measures this post-copy tail.

Streaming delivery is a global opt-in layered on auto-paste. When the provider supports `StreamingTextTransformer`, Accessibility is trusted, Secure Event Input is off, and the run is eligible for direct delivery, `StreamingTypist` pins the frontmost application and posts Unicode key events in grapheme-safe chunks with a 20-UTF-16-unit target. Its pure `TypingStep` planner separates text from line breaks, treating CRLF as one break. Line breaks use Shift-Return so chat editors do not submit a message. Target and secure-input checks run before each posted step. If no frontmost application identity is available at startup, the typist refuses to activate and the run uses atomic delivery. `AppState` retains an active typist as run-scoped state, so Esc cancels its pending cadence synchronously before the pipeline returns to idle. Deltas are coalesced on a 50 ms cadence or 200-character buffer. Atomic and streamed delivery share one output normalizer; the typist retains at least two characters and expands that holdback through the last non-whitespace character plus all trailing whitespace. Quote-prefixed output remains buffered until completion because matching-wrapper removal and unmatched-leading-quote preservation cannot be decided irreversibly earlier. Focus changes, secure input, or event failures stop typing permanently for that run; generation may finish and the complete normalized result is still written to the clipboard once. Successful streaming skips the final Command-V because the text is already present.

`AppState.lastResult` is derived from the newest successful `HistoryStore` record instead of a separate single-slot cache. If history capacity evicts the original success, a failed revision's preserved base output remains eligible as the last result; failed translation, custom, and contextual records never qualify. Copy Last and Paste Last select the newest successful output through `lastSuccessfulResult`, falling back to `lastResult` only when no successful output remains in history. Retrying an older revision cannot override a newer success for these actions. Revise starts from the same `lastSuccessfulResult`; `lastResult`, which can also be a failed revision's preserved base, only decides whether the revise shortcut is offered. Copy Last reuses the pasteboard writer and success feedback; it is disabled until a result exists.

Models picks the global provider via radio rows with trade-off tags and gives the API key an explicit Saved/Not set lifecycle (Change/Remove) backed by `KeychainStore`. Permission state lives in `PermissionStatusModel`; actions refresh it on completion and whenever the app becomes active, then refocus visible windows so TCC/System Settings handoffs do not bury Syrup behind other apps.

`FnKeyMonitor` handles the optional Fn trigger. Carbon hotkeys cannot express a modifier alone, and the recorder never sees one, so it polls the key state at 30 ms only while the option is on. This needs no Accessibility or Input Monitoring. `FnKeyGesture` treats Fn with any other key as not meant for Syrup, and marks a second tap that starts within 350 ms of a first tap under 300 ms. In hold mode a double-tap latches the run the second press started, with no delay to a hold. In toggle mode a double-tap from idle starts on the second release, a single tap stops a recording, and any other tap does nothing, including during transcription or transformation.

`OnboardingView` is the first-run window, a second `Window` scene (`OnboardingWindow.id`) with a hidden title bar. `OnboardingGate.resolve` decides whether it opens at launch and must run before `AppSettings` is created, because creating settings writes defaults. It stores `onboardingState` as `pending` or `done`. `OnboardingRecipe` holds the pure locale and workflow rules, `OnboardingArt` the drawn syrup, and `PermissionActions` the requests shared with Privacy. Its fields bind directly to `AppSettings`, and API keys go through `KeychainStore`. `AppState.holdsPasteForOnboarding` makes a run skip paste only when Syrup itself is frontmost, decided when the run starts.

`AppFeedback` owns user feedback outside the state machine: it plays the system `Glass` sound for successful clipboard writes and posts mapped error messages through `UNUserNotificationCenter`. Notification authorization is requested lazily with provisional options; if macOS denies or fails the request, the app simply keeps the icon/error-state feedback. Transformation-failure notifications carry only a history record UUID and expose only actions the snapshot supports; contextual records expose neither transcript fallback nor Retry. No transcript, output, workflow name, instruction, or selected text goes into notification payload text beyond the mapped error message. Success sound playback is controlled by `AppSettings.playSounds`, and successful writes briefly flash the menu bar symbol to `checkmark.circle`.

`RecordingCueController` shows a small floating cue at the bottom-center of the focused screen: a borderless, non-activating, click-through `NSPanel` (joins all Spaces, floats over full-screen apps) hosting `RecordingCueView`. The cue mirrors the whole pipeline via `RecordingCueState`: while recording it is a dark capsule with a drifting wave whose amplitude tracks microphone loudness plus the live "heard so far" transcript (volatile results streamed through the `Transcriber` protocol's `onPartialTranscript` callback, revealed by a `TranscriptTypewriter` at typing speed so chunked recognizer output reads as continuous words, and never persisted or logged); while transcribing the wave collapses into a slow breathing line; during transformation, streaming providers show a rolling 300-character output preview even when auto-paste and direct typing are off; success flashes a checkmark and errors flash the mapped user message with a red mark until the standard error reset fires. A small caption above the pill names the triggering workflow when it isn't the active one, says "Revising last result" for revisions, and switches to an "esc to cancel" hint after five seconds of recording. `syncRecordingCue()` derives the cue state from `pipelineState` + success-feedback flags in their `didSet`s, so the cue is a pure function of the state machine just like the menu bar icon (which additionally animates its symbol with a variable-color effect while recording or processing); the presenter is a `RecordingCuePresenting` seam injected by `SyrupApp`, absent in unit tests. Mic levels come from `AudioLevelTap`, which wraps the capture stream in `runPipeline` — it forwards each buffer to the transcriber unchanged and reports a per-buffer RMS smoothed by `LevelSmoother` (fast attack, slow release). The cue itself retains no audio: only the scalar loudness and the on-screen transcript text leave the cue pipeline, and both stay in memory.

Both cue behaviors are user-settable in General settings (`showRecordingCue` and `showLiveTranscript`, scalar bools defaulting to true). `preferFastTranscription` is a separate default-off preference: only that explicit choice adds `.fastResults`; volatile preview remains available in either recognition mode. Accurate recognition is the default regardless of preview visibility. Recognition quality and latency differences require comparison with consented audio fixtures; the downstream model is not assumed to repair recognition errors.

### History

`HistoryStore` keeps the newest 20 `DictationRecord` values. Each record stores the finalized transcript, optional transformed output, success/failure outcome, finish time, an optional effective provider identifier, and a `TransformationSnapshot` that can reproduce retry instructions even if the workflow is later edited or deleted. Transcribe-only records use a `.contextual` snapshot with an empty instruction and no provider and offer neither Retry nor transcript fallback. Their delivery writes the clipboard once and uses the normal atomic paste strategy even when streaming delivery is enabled. Revision of a transcription result constructs a revision snapshot and uses the global provider. History is in-memory by default. When Persist history is enabled, records are saved to `Application Support/Syrup/History/history.json`; the history directory is forced to `0700` and the file to `0600`. Corrupt history files are ignored and logged only by error code. Encoding and writes run on a dedicated actor in append order, outside the delivery path. Clear and persistence opt-out wait for pending writes and delete the file before confirming the change. At launch with Keep history off, a file left on disk (for example after the preferences were reset) is deleted (`deleteLeftoverFileIfPersistenceIsOff`). If that fails, Settings shows it with Try Again (`leftoverFileRemains`) instead of staying silent. Only the app calls it, because a test's store could point at the real folder; the shared test fixture defaults to a temporary one. Deletion failure preserves existing records and the opt-in state and exposes a message in Settings and the menu. Records appended during a clear survive that clear. Records made while persistence is off stay memory-only for the session and are never written, even after it is turned on (`HistoryStore.memoryOnlyIDs`); turning it off marks every current record that way. `AppSettings.persistHistory` is `fileprivate(set)`: the only way to change it is `PrivacyOptIns.setPersistHistory`, which has the store act first and changes the setting only if that worked. Quit waits up to 2 seconds for run work and then up to 2 more for pending history and usage-stats writes, so a stuck disk cannot hold the quit for more than about 4 seconds. Notifications resolve Copy transcript against their originating record ID and ignore missing or evicted records.

For retryable failures, Retry uses the failed record's snapshot instruction and recorded provider with that provider's current configuration. Switching providers requires the explicit Retry with another provider menu action. Legacy records without provider metadata remain readable and require an explicit Retry with provider choice; notification Retry is unavailable for those records. Every retry uses the current personal glossary, and its instruction is composed again from parts the record kept rather than edited out of a rendered prompt: target and tone for a translation, the spoken adjustment for a revision, and for a custom workflow its own instruction and output-contract choice (`TransformationSnapshot.CustomPrompt`, an optional field older builds ignore). A custom record from an older build has only the rendered instruction; `PromptBuilder.customPrompt(fromLegacy:)` recovers its parts by cutting the glossary block, found from the last vocabulary header that starts the text or follows a blank line, up to the output contract or the end. Only such old records are parsed this way. The retry's success record keeps what the retry sent: the recomposed instruction and, for a custom workflow, its parts, so an older record gains them and a deleted glossary term does not stay in history. A failed revision record keeps its spoken adjustment as the transcript and its captured base text in the record's output slot, making retry self-contained without a base-record ID; it never exposes transcript fallback. A successful retry appends a new success record; the original failed record remains as log history. Context-bearing and selected-text runs use `.contextual` snapshots whose instruction excludes captured text, so Retry and transcript fallback are disabled. Selected-text records store `transcript = ""`; the selection itself never enters history, including when Persist history is enabled.

### Secrets & settings

`KeychainStore.save`, `load`, and `delete` throw typed errors for failed file operations. Only a missing file means no saved key or a successful no-op deletion. Provider resolution never treats an unreadable key as permission to fall back to an environment endpoint. Settings reports a credential change only after the store operation succeeds.

`EndpointConnectionTest` associates each connection result with a request generation. Editing the endpoint, model, provider, or typed key invalidates the displayed result and prevents older requests from replacing it.

- Persistent app-entered API keys belong in the local app-support secret store through `KeychainStore` (legacy type name). The store writes one raw secret file under `Application Support/Syrup/Secrets/<service>/<account>.secret` with owner-only `0600` file permissions; both the `Secrets` root and service directory are forced to `0700`. It deliberately does **not** use macOS Keychain — originally because Debug builds were ad-hoc signed and triggered repeated Keychain password prompts as the code identity changed with every build. It logs only non-secret error domain/code values on unexpected file failures.
- Local builds use ad-hoc signing by default. Developers can override the signing identity and team to keep TCC permission grants stable across rebuilds. Distribution builds receive a Developer ID identity and team through the release command. Hardened runtime remains Release-only so LLDB can attach to Debug builds. The file-based secret store remains intentional.
- Non-secret scalar preferences live behind `AppSettings`: hotkey mode, legacy flat translation fields for migration/tests, global translation provider, OpenAI-compatible endpoint base URL/model, Codex CLI path/model, Claude Code path/model/account folder, success-sound toggle, auto-paste toggle, streaming-delivery toggle, Persist history toggle, maximum recording duration, and selected microphone UID. They are stored as raw strings/bools/integers in `UserDefaults`; the API key is never written to defaults.
- Workflows and the personal glossary are the structured UserDefaults exceptions. A glossary, proposal, or `workflowListV3` blob this build cannot use (data that does not decode, or an older version) is copied at load to `<key>.unreadable.<first 8 bytes of its SHA-256>` before the first edit replaces it; the copy is idempotent across launches. A backup holds user content, so writing one, or finding it already there, removes the key's other backups. Emptying the glossary keeps it: it holds content from before the blob became unreadable, which the person never saw or deleted. No released build wrote these backups (they arrived after 1.0 build 14), so several per key exist only on development builds, where the next load prunes them while that key's blob is still unreadable; otherwise they stay until that key's next backup. `outputVolumeRestore` (see `OutputDucker`) is the one other structured value: runtime state, not a preference. A newer build's blob is not copied, because it stays in place and is never overwritten. A provider name this build doesn't know (one a newer build added) decodes as nil, the default provider, in workflows and history records (`decodeProviderIfPresent`), and history loads record by record, so one unreadable record never costs the file. `WorkflowList` version 3 is encoded under `workflowListV3`. It imports versions 1 and 2 from `workflowListV1` without changing or deleting that key. Older builds cannot decode `transcribeOnly` and their writer can replace undecodable blobs, so a version bump in the same key would lose workflows on downgrade. The separate versioned key preserves new workflows while older builds see their pre-upgrade list. Edits made in an older build after migration do not merge into V3. A corrupt or older `workflowListV3` falls back to `workflowListV1` if that still reads, and otherwise to a default workflow; a newer build's `workflowListV3` loads the default workflow, as the settings rule says, never the stale V1 list. A version-only envelope protects future V3 blobs from writes even when their enum cases cannot decode. `GlossaryList` uses `glossaryV1`. The glossary normalizes whitespace, rejects empty terms, and keeps the first case-insensitive duplicate. Corrupt glossary data runs as an empty list and logs only an error code; future-version glossary and proposal blobs also run empty and are not overwritten, because every blob write goes through one version check (`persistVersioned`). An encode failure is logged by code instead of dropped silently.
- Settings' OpenAI-compatible test and every run share one precedence in `OpenAICompatibleSettingsConfigurationResolver`: typed API key first, then saved local API key, then complete process environment fallback when no non-blank saved key exists, then the saved endpoint with no key. A saved key that cannot be read is an error and never falls back; onboarding reports that error too rather than showing no key. The Privacy pane names the destination from the same resolution, so in a Debug build whose development environment overrides the saved endpoint it shows that host, marked as a development override. A non-loopback `http` base URL stays allowed for local-network servers, but Settings warns that the key and text travel unencrypted (`EndpointPolicy`). Codex CLI status checks run `codex --version` and check only for auth-file presence; they do not parse or log auth contents.
- `AppSettings` starts fresh under the `org.syrup.SyrupApp` defaults domain. Non-secret preferences from previous app names are intentionally not migrated.
- On a fresh install with no selected microphone preference, `AppSettings` defaults to the built-in microphone UID when Core Audio reports `BuiltInMicrophoneDevice`; otherwise it leaves the selection empty, meaning the system default input device.
- Launch at login is not stored in `UserDefaults`; `LaunchAtLoginController` mirrors `SMAppService.mainApp.status` and calls `register()`/`unregister()` through a small `LaunchAtLoginManaging` seam. The UI shows the system status (`Enabled`, `Off`, `Requires approval in System Settings`, or `Unavailable`) and keeps failures as local Settings state.

### Workflows

`Workflow` is the run-time configuration unit: name, `WorkflowKind`, input mode, optional selection-context flag, dictation locale, speech engine, and an optional provider override. `.voice` workflows dictate and may opt in to selected reference context; `.selection` workflows transform selected text directly. `.translation` workflows use target language + tone preset; `.custom` workflows use a user-authored instruction plus an optional system-owned output contract. `.transcribeOnly(cleanup:)` workflows are voice-only, with no selection context or provider override; decoding, construction, and mutations normalize these fields. Their finalized transcript bypasses provider preparation, configuration resolution, and transformation. `TranscriptCleanup` applies one language-subtag table for English and Portuguese fillers and spoken formatting, with Unicode letter/mark boundaries. Other languages receive only trimming. Empty cleanup output uses the existing empty-transcript error. Provider overrides choose among the existing global providers but do not own endpoint URLs, models, or secrets.

The default migrated workflow is "Translate" with Voice input, built from the legacy flat target/tone/dictation settings. Built-in templates create common one-shot workflows: Transcribe, Translate, Polish, Reply Draft (selection context enabled), Summarize, Prompt Writer, Summarize Selection, and Translate Selection. Workflows are deliberately one-shot and may skip transformation; no transcript, selection, or model context is carried between runs.

### Hotkey

Pausing removes the main, revision, workflow, and cancel handlers from KeyboardShortcuts. The controller retains their callbacks locally and restores the current workflow set on resume. Shortcut editor callbacks reapply that state so edits cannot leave shortcuts registered while paused.

`KeyboardShortcuts` handles registration + recorder UI in settings. The primary `.dictate` shortcut snapshots the frontmost app once and resolves `WorkflowList.appRouting`, a bundle-ID to workflow-ID dictionary, synchronously before recording or provider preparation. Empty routing skips bundle-ID retrieval. A missing route uses the active workflow. Explicit workflow shortcuts and revision ignore routing. Shortcut ownership remains the physical shortcut, separate from the resolved workflow ID used by the existing cue caption. Routing normalizes stale workflow IDs on decode and mutations, including deletion. Settings resolves only saved bundle IDs through LaunchServices for icons/names; application discovery uses NSOpenPanel only after Add application. Missing apps remain removable by bundle ID. App identities do not enter RunConfiguration or history, provider requests, logs, or notifications. The separate `.revise` shortcut defaults to ⌥⇧` and applies one spoken adjustment to the newest successful output. Additional workflow shortcuts use dynamically derived names (`dictateWorkflow-<UUID>`) and are one-shot: pressing a workflow hotkey runs that workflow without changing the active workflow. `HotkeyController` forwards key down/up events and the scoped Esc cancel shortcut into `AppState`.

`AppState` interprets the selected trigger mode: *hold* (keyDown starts, keyUp stops) or *toggle* (press starts, press again stops). During recording, only the same shortcut that started the run can stop it; another workflow or revise shortcut is ignored. The revise shortcut is inert during transcription and transformation, so it never cancels an active run. Esc is enabled only during recording, transcribing, or translating so it is not reserved while idle or showing an error. At launch and whenever workflow shortcuts change, `AppState` asks `TranscriberAssetManager` to prepare the active workflow locale and any voice locale attached to a bound workflow shortcut or configured app route. Configuring a route warms its speech locale through the same preparation path; unbound and unrouted inactive locales are not prepared.

### Concurrency

Swift concurrency throughout: the pipeline run is a `Task` owned by `PipelineRun`; cancellation is cooperative (`task.cancel()`). Audio buffers flow through an `AsyncStream` from the AudioQueue callback queue, and provider text deltas flow through `AsyncThrowingStream`. `StreamingTypist` is main-actor isolated because it pins `NSWorkspace` state and posts UI input events; provider streaming remains off-main. Passive preview consumes the same stream without input events and writes the clipboard only on successful completion. OpenAI-compatible streaming keeps the request timeout for the first response, then uses a cancellable deadline task reset only by a chunk whose choice carries something other than `role` (`OpenAISSEParser.progressChunks`, `JSONFieldValue.carriesSomething`): answer text, reasoning as a string, as structured `reasoning_details`, or as a part inside `content`, or a tool call with content; empty text parts and objects holding only `type` or `index` do not count. Keepalive comments, empty or usage-only chunks, and role-only deltas cannot postpone it. Until the answer starts, a streamed request also has a limit of ten times the timeout, five minutes by default, so a server that keeps sending reasoning or nothing without ever answering cannot hold a run; once answer text arrives that limit ends, and the inactivity deadline and the 8 MB cap bound the rest, so a slow model writing a long answer is not cut off, and `[DONE]` ends consumption without waiting for transport EOF. Some servers close the stream after a `finish_reason: "stop"` chunk without sending `[DONE]`; the parser task then ends the event stream with `.done` (`OpenAISSEParser.didReceiveStop`), so the run completes, while EOF with neither is still a connection failure. A final chunk may omit `delta`. A chunk with an `error` object or `finish_reason: "error"` fails the run with `TranslationError.providerReportedError`, even when `[DONE]` follows, so partial text is never delivered as a success. Every response, streamed or not, stops at 8 MB (`responseBodyLimit`) with `TranslationError.responseTooLarge`: a body that is not consumed as SSE, including the atomic request's, is read through `readResponseBody`, and `consumeSSE` counts every streamed byte, which also bounds a line that never ends. Deltas reset the inactivity deadline, so without this a model stuck in a loop would keep typing until Esc. `AppState` is `@MainActor`; audio/network work happens off-main.

`AppState.pipelineState` is `private(set)`; the phase files move a run on only through `enterProcessing(.transcribing / .translating)`. The voice run is `runPipeline`, a short sequence of named phases in `AppState+VoiceRun.swift`: open the microphone, await the run's configuration, start transcription, finish transcription at the stop, deliver the transcript (`AppState+Delivery.swift`), then count usage. `VoiceRunWork` holds the child tasks the phases share. Every trigger, release, revision, menu, and cancel event goes through `PipelineTransitions.command(for:in:run:hasLastResult:)`, a pure table that returns start, stop, cancel, or ignore; `AppState` performs the command and async completions move the state on. Delivery has one commit point, `commit(_:)`: the clipboard write, the success record, and `deliveryCommitted`, after which neither cancel nor a trigger re-press applies. `finishRunSucceeded` and `finishRunFailed` both return early for a run that no longer owns the pipeline. Atomic, streamed, and pause-transformed results all pass through it, and every failed transformation is recorded once by `recordFailedDelivery`, which stores the record's ID on the run so the failure notification offers that record's actions rather than an older record with the same message. The app delegate's `applicationShouldTerminate` calls `AppState.prepareForTermination()` on every quit path (menu, Command-Q, logout, update relaunch): it ends any run, then waits up to two seconds in total for every run task still returning, including a cancelled run still unwinding, and for the output volume to be restored, and then up to two more seconds to flush usage stats and history, so quitting takes at most about 4 seconds. Run tasks are tracked from launch until they return; `waitForPendingWork()` awaits the same set without a limit, which tests use before asserting that nothing else happens.

When typing a stream into the editor, `StreamingTypist` checks the pinned field through Accessibility once per flush, off the main actor, and only the frontmost app and Secure Event Input between keystroke steps. Flushes run one at a time on a single chain: each awaits its focus check, then rechecks that the typist was neither cancelled nor stopped while it waited, then posts the pending text. Deltas that arrive meanwhile queue behind it, so text keeps its order, and Esc still stops all posting at once. `finish()` and direct `typeText(_:)` are async for the same reason.

Each `PipelineRun` begins one `ProcessInfo` activity with `.userInitiated` options and a fixed reason when it is created, through the `ProcessActivityControlling` seam. The run alone holds the token. `clearRunTracking()` ends it, which covers success, cancellation, failure, and supersession. The activity keeps App Nap and idle system sleep from interrupting a run.

### Latency instrumentation

`PipelineMetricsRecorder` records privacy-safe stage durations with `ContinuousClock`, `Logger`, and `OSSignposter`. The metrics include only the pipeline stage name, a per-run UUID, and duration; they never include audio, selections, transcripts, translations, prompts, endpoint URLs, API keys, model names, or clipboard contents.

Current app-level spans cover selection capture, hotkey-to-recording-started, release-to-recorder-stopped, transcription-window, release-to-transcript, translation configuration, translation, first streamed delta, first visible output, clipboard write, auto-paste, and release-to-clipboard. `selection_capture` records duration only, never selection contents or length. Delivery records only the privacy-safe mode `atomic`, `streamed`, or `streamed_partial`. The `transcription_window` span starts when live transcription begins, so it includes the recording window by design. `release_to_recorder_stopped` starts at the stop request and includes the release tail. The latency regression gate asserts that transcription and translation-provider preparation begin before release; Release QA treats couple-sentence translation-shaped OpenAI-compatible `release_to_clipboard` above roughly 3 seconds or a sustained 20% same-machine regression as requiring explicit acceptance. Custom workflows are measured but not gated by the translation-shaped target because output length is instruction-dependent. Lower-level speech and provider spans can be added behind the same recorder as the pipeline is optimized. Two more log lines carry numbers only: `quiet_before_release_ms`, the time from the last loud buffer to the stop request in voice runs, recorded with early transformation off as well; and, for runs eligible for early transformation, `pause_transformation` (`hit`, `miss`, `none`, or `failed`) with the attempt count. A hit records its transform duration as the `translation` stage.

`AppleTranscriber` also emits privacy-safe Speech-stage signposts for asset readiness, analyzer format lookup, prepare/start, audio conversion/feed, finalization, and result collection. These logs use only stage names, an ephemeral transcription UUID, outcome, and duration.

The audio conversion/feed loop runs through `AnalyzerAudioFeedWorker`, an actor that owns the mutable `AVAudioConverter` state. This keeps the CPU-heavy buffer conversion path off `AppState`'s main-actor isolation while the UI state machine stays main-actor bound.

Speech authorization callbacks can arrive on a TCC background queue. Settings requests speech permission through `SpeechPermissionRequester`, a nonisolated async bridge, so SwiftUI button closures do not inherit `@MainActor` isolation and trap when TCC calls back off-main.

## Testing strategy

- Protocol-based seams (`Transcriber`, `TextTransformer`, selection reader, clipboard, auto-paste, clock) → the state machine and pipeline are unit-testable with mocks (Swift Testing framework). `AppState.init` has no production defaults, so a test cannot reach a real service by omission.
- `PromptBuilder` is pure → table-driven tests over language/tone/workflow and revision instructions, plus glossary/context composition, ordering, absence, and glossary truncation.
- `OpenAICompatibleTransformer` tested against a stubbed `URLProtocol`; `CodexCLITransformer` tested with a fake `CommandRunning` seam and a narrow process-runner timeout regression.
- SSE parsing accepts LF, CRLF, and CR line endings across chunk boundaries. Cumulative-snapshot adaptation, inactivity tracking, streaming delivery decisions, and `StreamingTypist` focus/secure-input/Unicode behavior have focused deterministic tests with injected seams.
- `HistoryStore`, `AutoPaster`, workflow settings/migration, glossary model/storage, and on-device availability/error mapping have focused tests.
- Speech engines are tested with fake transcribers, a fake `SpeechModelProviding`, a fake `ParakeetDecoding` for segmentation and the speech check, and injected `SpeechModelManager.Operations`, so tests never load FluidAudio models or download anything.
- `PipelineTransitions` is pure, so the whole event table is tested directly; `AppState` tests drive real transitions rather than setting the state.
- Tests build settings on `TestDefaults`, an in-memory `UserDefaults` subclass, so they write no preference files; `OutputDucker` takes its `UserDefaults` for the same reason. `AppState.fixture` defaults to a temporary history folder and an inert `TranscriberAssetManager`, so a test that leaves them out reaches no real file or speech-asset service.
- `HardRuleTests` asserts each AGENTS.md hard rule the code can check, named after the rule. Fixtures for downloaded files and provider responses follow published layouts and documented shapes, with their source named, not the shapes the code expects. A regression test is written first and seen to fail on the unfixed code, then the fix makes it pass.
- Async tests wait with `eventually`/`settleRun` (`Tests/SyrupTests/TestSupport.swift`), which fail after a wall-clock timeout instead of a fixed yield count, or on an explicit completion signal: `AppState.waitForPendingWork()`, the buffer-level metrics event (`recordBufferLevel`, a no-op in production), or a fake's counter. A test that asserts nothing happened after a cancel waits for the run's work to finish first (`waitForPendingWork`), so the assertion cannot pass before the work ran. The `Task.yield()` calls left in tests are scheduling nudges between a trigger press and its release, or come before checks that a synchronous transition left the state unchanged; none stands in for waiting on work. An ordering test holds the first operation inside its fake until the next run's `begin` has opened its session (`StreamingSpeechEngine.currentSession`, which the engine also uses to refuse calls from an earlier session), so the order it asserts is the one under test in every schedule. The shared pipeline fakes live in the same file.
- Under XCTest the app starts an inert host (`SyrupMain`), so neither `xcodebuild test` nor `script/test-isolated.sh` registers hotkeys, downloads models, or touches recordings.
- Audio + real speech recognition: manual smoke test checklist in `docs/QA.md` (simulator can't do this meaningfully).

## Key decisions (and why)

1. **Native Swift, not Electron/Tauri** — the app lives in the menu bar, needs low-latency audio, global hotkeys, and a tiny footprint. Native is strictly better here.
2. **On-device transcription, pluggable transformation** — audio never leaves the machine. A normal cloud-backed transformation receives only the final transcript plus its run instruction; a cloud-backed revision receives the captured previous result plus the current revision instruction. No unrelated history or content is sent. Apple On-Device keeps transformation local when Apple Intelligence is available.
3. **Transcribe-then-translate, not audio-to-LLM** — keeps the LLM interface to plain OpenAI-compatible chat completions, so any endpoint works, including local ones without audio support.
4. **Protocols at the two volatile seams** (speech engine, text transformer) — those are the parts most likely to change; everything else stays concrete and simple.
5. **XcodeGen** — project file as reviewable text; friendly to AI-agent edits and to git.
6. **Fresh settings for the product rename** — `org.syrup.SyrupApp` starts clean instead of migrating defaults or local secrets from previous app names. This avoids carrying forward stale menu-bar, hotkey, microphone, and endpoint state under a new brand.
7. **Milestone 9: Codex subscription via the CLI, not its backend API** — `chatgpt.com/backend-api/codex/responses` is avoided because it is undocumented and would require implementing OpenAI's OAuth flow and token refresh ourselves. Spawning `codex exec` delegates all of that to the officially maintained CLI at the cost of a subprocess (~1–3s extra latency) and requires App Sandbox to be off. We deliberately do not keep a warm Codex process; the CLI is the slower, subscription-backed provider, while OpenAI-compatible and Apple On-Device are the low-latency paths.
8. **`TranslationError` keeps its name** — providers now conform to `TextTransformer`, but renaming persisted settings and user-facing error plumbing would create churn without improving the model.
9. **Selected text is ephemeral run input** — selection capture is per-workflow opt-in, occurs at trigger press through Accessibility, rejects secure-text-field subroles before reading selected text, is capped at 20,000 characters, and is never logged or persisted. Contextual records cannot reproduce the original input, so Retry is deliberately disabled. A Command-C fallback is not implemented because even a snapshot-and-restore approach would violate the clipboard contract without a separate product decision.
10. **Streaming changes delivery, not clipboard atomicity** — capable providers may type append-only deltas into a pinned target to reduce perceived latency, but the clipboard is still written once with the complete normalized result. Cancel stops immediately and leaves any typed prefix because deleting unknown editor content is more destructive than leaving an obvious partial result.
11. **Parakeet is an opt-in final transcript, not a replacement.** On synthetic clips it recognized far more technical terms than Apple but damaged more ordinary Portuguese, so Apple stays the default. Apple keeps the live preview in Parakeet runs because FluidAudio's sliding window updated every 11 seconds by default and, at 2-second chunks, lost accuracy and used more CPU. Measurements are in [the speech engine comparison](docs/verification/2026-11-01-speech-engines.md).
12. **Parakeet Ultra replaced v3 rather than joining it.** On 200 real Brazilian Portuguese recordings it made 18% fewer word errors than v3 at the same speed, and FluidAudio already loaded it, so keeping v3 would only add a worse choice. Redux stays for its 220 MB download. See [the Portuguese model comparison](docs/verification/2026-11-03-portuguese-models.md).

### Source capture and delivery recovery

SelectionReader receives the process identity captured at trigger time. It checks the foreground process before and after its asynchronous Accessibility read, reads only that application's focused element, and verifies that element is unchanged after reading the selection. The captured element identity also pins delivery for selection-bearing runs. A source change aborts Selected text input and omits optional voice context with a notice. Secure-field rejection, trimming, the 20,000-character cap, cancellation checks, and exclusion of captured selections from history still apply.

OpenAI-compatible atomic and SSE responses inspect optional `finish_reason` values. `length`, `content_filter`, and `error` produce typed failures instead of final clipboard delivery or success feedback. Missing reasons remain compatible. A previously typed prefix can remain after a streaming failure and the existing partial-text notice applies. Preview accepts a successful `application/json` response as one completed result. HTTP 400, 422, or 501 activates atomic fallback only for a structured error whose `param` is `stream` and whose `code` is `unsupported_parameter`, `unsupported_value`, or `not_supported`. Other failures and interrupted streams do not automatically retry. JSON body reads have a bounded timeout.

A failed clipboard commit retains at most one completed result in memory, separately from history, and exposes Copy result again. That action retries only the clipboard write, appends success history only after delivery succeeds, and does not rerun transcription, transformation, or auto-paste. Its history snapshot contains no selected-text input or captured context. Repeated copy failures keep recovery available; the next successful pipeline delivery clears it. No failed-delivery result is written to disk before explicit successful recovery, and subsequent history persistence still requires Persist history.

## In-app updates

Source builds leave the update feed and public key empty. `UpdateController` starts Sparkle only when both are supplied by the publisher; visible update controls remain inactive without them.

`SyrupApp` alone creates `UpdateController`, which owns Sparkle 2.10.1's standard updater and delegates. Under XCTest, `SyrupMain` starts an inert host instead of `SyrupApp`, so tests never start an updater, hotkeys, downloads, or retention cleanup. Checks reject active runs, relaunch waits for foreground work to finish, and automatic downloads and system profiling stay disabled. Sparkle owns the automatic-check preference. Gentle scheduled reminders temporarily expose the app in the Dock. `script/release.sh` prepares reviewed artifacts separately from explicit publication. See `docs/UPDATES.md`.

## Transcript corrections

`Workflow.corrections` decodes to an empty list for existing workflows. `RunConfiguration` snapshots the table at the trigger. `Correction.apply` gathers matches from the original string, resolves overlaps by length, position, and table order, then replaces from the end. It preserves canonical Unicode matching without normalizing unrelated text. Hyphens are correction boundaries. Apostrophes are boundaries only at a trailing possessive `s` with a boundary after it; contractions remain whole words. `TranscriptCleanup` retains its own stricter boundaries. The finalized voice transcript is corrected before transformation and Transcribe cleanup.

## Paste last

The unbound `KeyboardShortcuts.Name.pasteLast` and menu action call `AppState.pasteLastResult`. With automatic paste off it is Copy Last and touches no Accessibility API, since the permissions rule reserves Accessibility for opt-in delivery. Otherwise it captures the current target and delegates to `pasteCompletedText`, shared with atomic run delivery, which returns whether the text reached the editor. When it did not, or no editor was captured, Paste Last shows the copied flash every time, because the notice for missing Accessibility appears only once per launch. Once it has copied, an error still on screen is cleared, as Copy Last does. A request ID and pipeline-state checks prevent delayed delivery after a new run or newer paste request. It does not create a transcription run, prepare a provider, or append history.

## Spoken formatting

`WorkflowKind.transcribeOnly` owns `cleanup` and `spokenSymbols`. Other kinds cannot hold the symbols option. The additive option stays in `workflowListV3`; missing values decode as false, and the built-in template defaults off. `RunPurpose` snapshots both options. With symbols off, `TranscriptCleanup` runs the cleanup algorithm from `78b2b47` unchanged. When cleanup is on, legacy cleanup finishes before symbols expand. Removing fillers before symbol joining prevents filler deletion from consuming a generated symbol. Symbol replacement keeps emitted punctuation protected from subsequent padding removal. Symbols use locale-keyed English and Portuguese replacement rules with explicit joining behavior. Cleanup and symbol toggles are independent.

## Smart spacing

`PipelineRun` snapshots the opt-in preference. When automatic paste and spacing are both on, target capture also runs if target pinning is disabled. `DeliveryTarget.caretContext(readsSentence:)` queries the pinned element's caret range and `AXStringForRange`. With smart spacing alone it reads one UTF-16 unit before the caret; caret fit widens the read, as described below. It returns only a word-character boolean and enforces a 100 ms operation deadline in addition to the existing AX messaging timeout. It excludes selections, secure fields, and changed targets. A supplementary character that cannot be read as one UTF-16 unit falls back without a prefix. Isolated combining marks are not word characters. This avoids spaces after emoji variation selectors and keycap marks. A decomposed accent ending in a combining mark also falls back without a prefix; a precomposed accented letter qualifies. Caret text remains local to that query.

Atomic Command-V delivery types the prefix separately; direct typing prepends it to the delivered text. Neither changes the clipboard. Streaming reads before its first nonempty delta and emits the prefix once. With the preference off, there is no added AX read or target revalidation.

The streaming typist holds a requested leading space separately from provider text. It adds the prefix once when normalized text first posts, including finish-only streams and size-triggered flushes. Provider-output normalization stays unchanged.

## Caret fit

`matchesSentenceAtCaret` is a default-off raw preference that `PipelineRun` snapshots at trigger. It does not need automatic paste, because it shapes the clipboard; onboarding's Taste page, where Syrup itself is frontmost, holds it off. It needs Accessibility trust to read the editor. For each delivered result (dictation, Transcribe, revision, retry, and an early-transformation hit), `DeliveryCoordinator.sentenceFit` reads the cursor once, immediately before the clipboard write: at the pinned editor while it is still current, otherwise at the focused element of the app in front, never Syrup's own, which is where a manual Command-V lands. The read is `DeliveryTarget.caretContext(readsSentence: true)`, under the same 100 ms deadline and exclusions as smart spacing. It reads up to 64 UTF-16 units before the insertion point and 16 after it, or around a selection being replaced, bounded by the field's character count when the editor reports one. An unreadable tail counts as no text following, and an editor that refuses the wider read falls back to smart spacing's one-unit read. Only three booleans leave the probe: a word character immediately before the caret (smart spacing's unchanged rule), whether the text before continues a sentence (a letter, number, comma, or semicolon on the same line; a colon, sentence-ending punctuation, a line break, or the start of the field do not), and whether a letter or number follows on the same line. Caret text is never stored or logged. The read adds at most 100 ms before the clipboard write, and only with the preference on.

`SentenceFit.apply` changes at most two things. When the sentence continues, it lowercases the first letter of a first word capitalized like a sentence start: not "I" or its contractions, not all capitals, no inner capitals or digits, not the start of a glossary term, and not a personal, place, or organization name according to `NLTagger`. When text follows, it removes one final period unless the last word is an abbreviation. The clipboard, a failed write's Copy result again, and any paste carry the fitted text. History keeps the exact result, so Copy Last copies it unchanged and Paste Last fits it again for its own target before writing and pasting. Automatic paste pastes the clipboard as for any result, with Command-V or Chromium typing, and smart spacing reuses the same read for its leading space. Streaming decides the first word before posting any text, holding an incomplete first word or a possible glossary prefix, and holds the final token until completion so the period decision never touches posted text; at completion the clipboard gets the same fit from the same context, so typed text and clipboard match. A stream that typed nothing reads the cursor at completion, like atomic delivery, even if it read one for its first delta: the person may have moved to another field before anything was typed.

## Input transport policy

`AudioInputDevice` carries Core Audio's transport type. `InputResolution` applies the raw default-on `avoidBluetoothMicrophone` preference only when the saved UID is empty and the current default has Bluetooth or Bluetooth LE transport. It prefers an available built-in microphone with the lid open or unknown, then a non-Bluetooth real input, excluding virtual, aggregate, and zero-channel devices. With no alternative it keeps Bluetooth. Saved choices and non-Bluetooth defaults retain their existing resolution, including closed-lid handling. Hardware discovery reads the transport property; the decision matrix is pure and tested without audio capture.

## Early transformation

`transformsOnPause` is a default-off raw preference. `PipelineRun` freezes it at trigger with the provider snapshot and the speech-engine selection. A run is eligible only for voice dictation (not revision, Transcribe, or selected-text input) transcribed by Apple alone, with Apple On-Device or an OpenAI-compatible endpoint whose host is loopback (`EndpointPolicy.isLoopback`), which a provider snapshot reports through `TransformerSnapshot.permitsUnfinalizedInput`. Loopback keeps the unfinished transcript on this Mac only if the local server does not itself forward requests elsewhere, which Syrup cannot see. Codex CLI and every other host are excluded, because an attempt sends a transcript that is not final yet. An attempt records the instruction it was sent with and is used only when both its input and that instruction match the run's final ones (`PauseTransformation.attemptMatches`): a pass can start while the selection is still being read, and output made without the context is never delivered.

An eligible run copies its captured audio in memory through `PauseAudioCapture`, up to 90 seconds; past the cap the copy is dropped and no new attempt starts. The copy is lock-protected and fills on the audio path, never on the main actor, and it is never written to disk. After 300 ms below `ReleaseTail.quietLevel` while capturing, a separate `AppleTranscriber` pass transcribes a snapshot of the copy with the run's locale, speech vocabulary, and recognition mode. Loud audio cancels a pending pass, and one pass runs per quiet period. A non-empty corrected transcript starts a `PauseTransformationAttempt`: a fresh transformer from the frozen snapshot, never the run's prepared one, because Apple's prepared session would keep the exchange as conversation history. It calls the atomic transform and has no delivery, history, or feedback side effects, and its errors count as a miss. Identical input keeps the running attempt; different input replaces it.

At release the attempt is used only when its input has the same UTF-8 bytes as the final corrected transformation input. A hit awaits the attempt and commits through the atomic path: one clipboard write, success history, and auto-paste, also with streaming delivery on. A mismatch cancels the attempt, and a failed attempt falls back; both then run the ordinary path. Cancellation, failure, and supersession cancel the pass and the attempt and clear the audio copy.

Apple's live partial results are not the trigger. On synthetic clips they matched the final transcript only 1.2 to 1.4 seconds after speech ended in fast mode, and never before release in accurate mode. An offline pass over the audio so far matched the release transcript in 87.5% of trials 300 ms after speech and in all trials at 600 ms in accurate mode, in a median of 76 to 92 ms. Real hit rates depend on how long people stay quiet before releasing; `quiet_before_release_ms` measures that. See [the early transformation verification](docs/verification/2026-11-05-early-transformation.md).

## Mishearing suggestions

`MishearingSuggestionModel` is `@MainActor @Observable`, created by `SyrupApp` and injected into the Syrup window's environment. It checks glossary terms one at a time in up to three dictation locales, taken from the voice workflows with the active workflow first. For each locale `MishearingProbeEngine` picks up to two system voices: the exact locale first, then quality, then the `com.apple.voice.*` voices over Eloquence and older voices, and never novelty or personal voices. It speaks the term inside a neutral carrier sentence in Portuguese or English ("Eu falei sobre … hoje.", "I talked about … today."; other languages speak the term alone) with `AVSpeechSynthesizer.write`, into memory only. `AppleTranscriber` transcribes that audio with the composed speech vocabulary through a check-only asset path that never requests Speech permission or starts a download. The carrier words must match at both ends, ignoring case, accents, and punctuation, or the sample is discarded.

A heard form that differs from the term and its existing mishearings (by case, whitespace, and edge punctuation; accents count) becomes a suggestion, up to three per term. A form needs at least two letters and at most two words more than the term, which drops carrier spill. `MishearingProbeResult.everydayForms` marks forms made only of correctly spelled words in the language that produced them, using the system spelling dictionaries, because such a hint ("those" for OAuth) can pull a provider into rewriting an ordinary sentence. Results and dismissals stay in memory. Accepting a form updates the term through `AppSettings`, so `glossaryV1` and every provider prompt include it. A dictation cancels a running check, and no check starts during one. Logs carry no terms or heard forms. Parakeet is not probed. See [the mishearing suggestions verification](docs/verification/2026-11-05-mishearing-suggestions.md).
